## Field schema — script-generated, never hand-filled

**Physical role** (relaxed_candidate / constrained_model / off_equilibrium_training)
is decided by the *actual* constraint and relaxation state, not by which family a
structure belongs to. Two extra fields travel with it:
- `relaxation_status`: not_run / relaxed
- `morphology_restraint`: none / <specific constraint, e.g. "top-layer registry fixed">

Fixing the bottom reference layers (a slab-boundary approximation used everywhere) is
NOT the same kind of constraint as forcibly fixing a defect's shape or registry — the
two must be recorded separately, not both collapsed into "constrained_model."

**Pipeline status**: planned / geometry_only / converged / qc_passed. An entry with no
generated coordinates yet is `planned`, not `geometry_only`.

**Per-structure geometry record** (script output only, atom counts in tables below are
provisional until confirmed by this record):
`N_base, N_added, N_removed, N_total, in_plane_cell_vectors, L_parallel, L_perpendicular,
terrace_width_upper, terrace_width_lower, defect_image_min_distance,
periodic_connectivity (finite / merged_strip / merged_network),
step_microfacet_per_edge {terrace_orientation, step_edge_direction, step_microfacet,
step_label, step_label_convention}, minimum_Au_Au_distance, reference_id`

Matched flat/undefected references (one per distinct in-plane cell + layer count +
constraint scheme) are auto-generated by script and do NOT count against the
20–30 parent budget.

## Correction 1 — A/B step-label convention was inverted

Correct convention: **A-type = {100} microfacet, B-type = {111} microfacet.**

| surface | step microfacet | label |
|---|---|---|
| Au(211) | {100} | A-type |
| Au(221) | {111} | B-type |
| Au(332) | {111} | B-type |
| Au(554) | {111} | B-type |

Au(211) [3(111)×(100)] and Au(221) [n(111)×(111)] differ in both microfacet type *and*
terrace width at once — comparing them can't cleanly isolate "step type" alone; this
limitation gets stated explicitly wherever the pair is used, not papered over by
adding more surfaces. Primary fields carried per structure are `terrace_orientation`,
`step_edge_direction`, `step_microfacet`, `step_label`, `step_label_convention` — the
A/B letter is a derived label, never the primary field, so a source using the opposite
convention can't silently flip a result.

|---|---|---|---|---|---|

| Step-16x4 | 16×4 | 256 | 32 | **288** | geometry_only — poscar regenerated at this size (288 atoms confirmed), **not yet re-rendered**; the previously published report image is still the old Step-8x4 render, not this one |
| Step-24x4 | 24×4 | 384 | 48 | **432** | planned |

Rev 1 had written 160/288/416 — it reused Step-16x4's actual 32-atom strip count for
all three sizes instead of rescaling with nx·ny. Fixed here; going forward atom counts

Still open: this is a **fixed-half-coverage** series (both terraces widen together as

Width must be measured along m̂ = ẑ×t̂ (t̂ = step direction), not as half a
(non-orthogonal) lattice vector — see the measurement in the Batch 1 results below.

## Correction 3 — island/pit base cells were geometrically infeasible

A 4×4 (64-atom) base has 16 lattice sites per layer. 19 same-layer, same-registry,
non-overlapping atoms cannot fit in that periodic cell — not a boundary-effect
concern, a hard infeasibility. Even 7 atoms at 7/16 = 43.75% coverage is too dense to
assume isolation from its own periodic image by default.

Corrected screening starting points (starting points for geometry screening, not
converged final sizes — final size is set by real coordinates, connectivity, periodic
distance, and later response convergence):

| structure | starting cell | note |
|---|---|---|
| Island-7, Pit-7 | 6×6 | still needs edge–image distance check |
| Island-19, Pit-19 | 8×8 | elongated shapes may need larger/different aspect ratio |
| compact/elongated pairs | same cell, sized for the elongated shape | keeps shape and periodicity from being conflated |

Mandatory automated check for every island/pit: is it still finite under PBC, or has
it merged with its own image into an infinite strip/network (island) or trench (pit)?
If merged, it gets renamed, not kept as "isolated island/pit" — this bears directly on
whether the continuum ion model can actually resolve it as a separate feature.

## Correction 4 — kink periodicity was underspecified

Need both `L_parallel` (period along the step direction) and `L_perpendicular`
recorded, plus the periodic-equivalent nearest spacing s_min = min(s, L_parallel − s).
In a short along-edge period, increasing s from 0.4·L to 0.8·L actually *decreases*
s_min from 0.4L to 0.2L — a "long" spacing can be closer to the far mirror image than
the near one if this isn't checked.

Plan: define short/long spacings inside the *same*, sufficiently long along-edge
period; separately test coupling against an even longer period before trusting either
as "isolated." This round: plan (not build yet) extending the along-edge repeat from
today's 4 primitive rows (the "4" in "16×4") to 8. After construction, re-count actual
kinks produced — an atom-conserving rearrangement can create more than 2 corners, or
simultaneous edge vacancies + bulges; a kink pair is confirmed by inspection, not
assumed from "moved a set of atoms."

## Reference structures

Every modified-Au(111) structure (steps, islands, pits, composites) gets a matched
flat reference at the same in-plane cell, layer count, and constraint scheme,
auto-generated by script — not a separate parent slot. High-index vicinal slabs are
compared to Au(111) via consistent potential/numerics and area- or step-length
normalization, never by subtracting against a geometrically-invalid same-cell flat
"(111) co-parent."

## Slab thickness

4 layers stays the working baseline, explicitly **not** a validated production
thickness. A 4-layer vs. 6-layer (and, if needed, 8-layer) comparison on the flat
reference and one representative step is planned, not submitted, this round.
VASPsol++'s own Au(111) benchmark used a 6-layer slab — this doesn't prove 4 wrong or
6 universally sufficient, only that 4 isn't an unchecked-safe default. Separately: a
monolayer pit in a 4-layer base leaves only 3 atomic layers under the pit floor —
pit-floor/back-side coupling is worth checking specifically, likely more sensitive
than the flat 4-layer case.

## Diagram requirements

Each representative structure gets: central-cell top view, key-direction side view,
**and a periodic-mirror view** (neighboring cell copies shown) — mandatory for
islands/pits/kinks specifically, since a single isolated crop can visually disguise an
actually-merged periodic strip/network as a finite island. Diagrams mark: cell
boundary, upper/lower terrace, step direction, microfacet type, defect size, and the
actually-measured periodic distance (not a nominal one). Compact and elongated islands
use the same visual scale; different layers/defect atoms may be color-distinguished
but never rendered with occlusion hiding overlapping atoms.
